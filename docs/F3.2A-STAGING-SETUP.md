## Isolation contract

Staging is intentionally separate from the production custom domain and must never alter `CNAME` or deploy to `lucasmorenopersonal.com.br`.

The workflow builds `.staging-dist` from the static production assets and adds staging-only controls:

- `robots.txt` with `Disallow: /`
- `X-Robots-Tag: noindex, nofollow, noarchive`
- no repository `CNAME` in the staging artifact
- exact source commit recorded as `STAGING_COMMIT_SHA`
- deployment restricted to pushes on `lm-2.0-rebuild` or manual workflow dispatch

## Required GitHub environment secrets

Create or use the GitHub Actions environment named `staging` and add:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`

The API token must be scoped only as broadly as necessary for Cloudflare Pages deployment/project management in the intended account.

Do not commit either value to the repository.

2. Add `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` as environment secrets.
3. Re-run failed jobs for run `33900144233`, or dispatch `LM 2.0 Staging` manually.
4. Require all workflow steps to PASS.
5. Capture the workflow summary values:
   - `STAGING_URL`
   - `STAGING_COMMIT_SHA`
6. Verify that `STAGING_COMMIT_SHA` equals the branch HEAD being validated.
7. Resume `F3.2 — Conversion Staging Validation` against that URL.
