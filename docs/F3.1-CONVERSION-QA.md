# F3.1 — Conversion QA & Analytics Foundation

## Scope

Validate the LM 2.0 conversion path without introducing a vendor dependency before the analytics account/container is defined.

## Conversion paths

| Path | Expected result |
| --- | --- |
| Header CTA | Scrolls to Consultoria; emits `cta_consultoria_click` |
| Hero primary CTA | Scrolls to Consultoria; emits `cta_consultoria_click` |
| Hero results CTA | Scrolls to Resultados; emits `cta_consultoria_click` with its source |
| Premium CTA | Opens qualification at question 1 |
| Audience CTA | Opens qualification at question 1 |
| Final CTA | Opens qualification at question 1 |
| Q1 → Q2 → Q3 | Progresses 1/3 → 2/3 → 3/3 |
| Back | Returns one step without losing the earlier answer until overwritten |
| Restart | Returns to Q1 and clears the qualification state |
| Premium route | Generates contextual WhatsApp link for Consultoria Premium |
| Training route | Generates contextual WhatsApp link emphasizing training need |
| Footer contact | Opens direct WhatsApp without qualification |

## Modal/accessibility contract

- Uses native `<dialog>` modal semantics.
- Initial focus moves to the first actionable choice.
- Focus stays inside the native modal while open.
- Escape closes the dialog and records `close_reason=escape`.
- Backdrop click closes the dialog and records `close_reason=backdrop`.
- Close button records `close_reason=close_button`.
- Focus returns to the CTA that opened the dialog after close.
- Progress copy uses `aria-live=polite`.
- All choices and navigation controls are native buttons or anchors.

## Analytics schema

Events are pushed to `window.dataLayer` and mirrored as `lm:analytics` CustomEvents. No GA4/GTM vendor snippet is installed yet.

### Base context

Every event receives:

- `lm_session_id`: random session-scoped identifier; no name, phone, email or health data.
- `page_path`
- `page_title`
- `viewport`: `mobile`, `tablet` or `desktop`
- `referrer_host`
- available session attribution: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`

UTM attribution is stored only in `sessionStorage` and reused during the current browser session.

### Funnel events

- `page_view`
- `cta_consultoria_click`
- `qualification_started`
- `qualification_q1_answered`
- `qualification_q2_answered`
- `qualification_q3_answered`
- `qualification_back`
- `qualification_restart`
- `qualification_completed`
- `qualification_closed`
- `whatsapp_click`

## Measurement model

Primary funnel:

`page_view → qualification_started → qualification_completed → whatsapp_click`

Useful diagnostics:

- CTA source by `source`.
- Qualification abandonment by `step` + `close_reason`.
- Route mix by `route=premium|training`.
- Acquisition by UTM fields.
- Device class by `viewport`.

## Privacy boundary

The analytics layer does not persist qualification answers. Answers are used in-memory to build the WhatsApp message and may appear in conversion events only while the page is active. Do not forward answer fields to advertising platforms without a separate privacy review.

## Manual browser QA before release

Test at minimum:

- 360 px mobile viewport
- 390–430 px mobile viewport
- tablet viewport
- desktop ≥ 1024 px
- keyboard-only navigation
- Escape/backdrop/close-button exits
- all three Q3 routes
- WhatsApp URL encoding with accented Portuguese text
- refresh with UTM query string and confirm attribution in `window.dataLayer`
- refresh without UTMs in the same session and confirm attribution continuity
- private/incognito window with storage restricted; flow must still work

## Release gate

F3.1 is code-complete when the scripts load without console errors and the manual matrix above passes in the deployed environment. Vendor analytics activation is a separate step requiring the real GTM/GA4 identifiers.
